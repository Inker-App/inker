# INKER

macOS menu bar app plus local MCP server that lets AI chat apps (Claude first) and agents work on sensitive documents without seeing the identifying details. Read `docs/stack-decision.md` before changing architecture; it records every decision and the open questions. The product brief is `docs/handoff/HANDOFF.md`; the design boards are `docs/handoff/design/` (App v2 page is the build target).

## Rules that are not negotiable

- **Never commit real PII.** Only synthetic documents, generated by `samples/` tooling, using values from the IRS's own invalid ranges (SSN area 000, 666 or 9xx; EIN prefixes that are not issued; routing numbers that fail the checksum unless the test needs a valid one, in which case use the Federal Reserve's published test numbers). The pre-commit hook in `scripts/` rejects anything that looks real.
- **Real values never leave the core.** Nothing returned to an agent, written to a log, or placed in an agent-visible location may contain a real value. `tracing` output must only ever carry tokens, handles and counts.
- **UI and UX decisions are Ben's.** If a screen needs something the designs do not show, ask. Internal code structure is ours.
- **Copy says "INKER", never "the octopus".** The octopus is the drawing and the 🐙/ prefix, not a name the copy uses. Coding agents are a side feature (Settings), never the pitch; Cursor is CLI-only.
- **The UI says "ink", not "redact."** "Ink it", "6 inked", "3 inking". Tokens render as `[SSN_1]`. Handles render as `🐙/codename` or `ink/codename`.

## Layout

```
core/      Cargo workspace (Rust). Builds and tests on Linux and macOS.
  crates/inker-core      vault, tokens, handles, codenames, document model, index
  crates/inker-extract   PDF text + AcroForm + OCR trait, pure-Rust implementations
  crates/inker-detect    rules, checksums, templates, model runner, treatments
  crates/inker-packs     loads packs; packs/tax is the first
  crates/inker-ipc       unix-socket host inside the app; JSON-RPC framing
  crates/inker-mcp       rmcp server: list, resolve, describe, write
  crates/inker-ffi       UniFFI bindings for the Swift shell
  bins/inker             CLI: ingest, list, resolve, serve, mcp (stdio shim), doctor
app/       Swift package: AppKit NSStatusItem + NSPopover hosting SwiftUI, Metal renderers
packs/tax  form templates (TOML) and codename rules, data not code
samples/   synthetic documents and the generator
scripts/   pre-commit PII check, release helpers
docs/      decision record, handoff
```

The website for inker.sh lives in its own repository (`../inker-site`), not here.

## Building

On this Linux box cargo is at `~/.cargo/bin`; export it: `export PATH="$HOME/.cargo/bin:$PATH"`.

```
cd core && cargo build --workspace
cd core && cargo test --workspace
cd core && cargo clippy --workspace --all-targets -- -D warnings
cd core && cargo fmt --all --check
```

The Swift shell in `app/` only builds on a Mac with Xcode 26: `cd app && swift build`, then `make app` to assemble `INKER.app`. See `app/BUILD.md`.

## Test-driven, always

Ben's instruction: build with TDD. Write the failing test first, see it fail, write the minimum code to pass, refactor green. No public function, tool, subcommand or template without a test that exercises it. Rust: unit tests in the module plus integration tests in `tests/`, fixtures from `samples/synthetic/`. Swift: Swift Testing in `app/Tests/`, logic kept in plain types so `swift test` covers it without AppKit. Python scripts: a sibling `test_*.py`. A change that adds behaviour without a test is not done.

## Conventions

- Rust edition 2024. `thiserror` for library errors, `anyhow` only in `bins/`. No `unwrap`/`expect` outside tests (workspace lints warn).
- Every crate depends on `inker-core` for shared types (`core/crates/inker-core/src/types.rs`). Add new shared types there, not in a leaf crate.
- macOS-only capabilities go behind the traits in `inker-core::ports`. The pure-Rust fallbacks in `inker-extract` keep the pipeline testable on Linux.
- Tests for detection run against `samples/synthetic/`. Add a fixture before adding a recognizer.
- Logs: `tracing`, never `println!` in library code.
- Commit messages: imperative, one line, body explains why.
